# GuardFil v0.1.0-alpha.4

Fourth alpha release · 2026-11-22 · GNU AGPL v3

GuardFil runs supported AI coding agents in a constrained executor and applies
owner policy to their shell, file and tool requests. This source release builds
on [v0.1.0-alpha.3](v0.1.0-alpha.3.md) with graceful broker listener shutdown on
`SIGTERM`, secret-free upstream SSE error diagnostics in the OpenAI broker,
schema-v2 provider ledger naming with crash-safe CLI migration, and an
`up --no-build` startup option with bridge-DNS build troubleshooting. It is for
a single user on a Linux machine with Docker; the quickstart builds the local
container image, and no prebuilt binaries or registry images are attached.

## Install

You need Linux (kernel 5.6+) with FUSE 3 (`user_allow_other` enabled in
`/etc/fuse.conf`), Docker with Compose, Python 3.11+, and the native agent you
want to run installed on the host. CI tested Codex 0.166.0 and Claude Code
2.1.318. Other versions are not covered by this release's native-agent
evidence.

```sh
echo user_allow_other | sudo tee -a /etc/fuse.conf
git clone --branch v0.1.0-alpha.4 --single-branch https://github.com/reviaro/GuardFil.git
cd GuardFil
deployments/local/guardfil-local.sh check
deployments/local/guardfil-local.sh init --ui active
```

Continue with the [README quickstart](../../README.md#quickstart) to add a
host-only provider key, start GuardFil and run an agent. Provider requests
cost money and are subject to the spending ledger; each provider starts with
its own $2.00 ceiling.

## Upgrading from alpha.3

- Run `deployments/local/guardfil-local.sh up` to rebuild the service container
  image and extract updated `guardfil-broker`, `guardfil-mcp-proxy` and
  `guardfil-workspace` helpers. (If `docker compose build` hits a bridge DNS
  timeout on your host network, build on `--network=host` from the repository
  root and pass `up --no-build`.)
- If your `~/.local/state/guardfil/` directory contains ledgers from earlier
  alpha releases (`t2a-experiment`, `anthropic-experiment`, or
  `gemini-experiment-6`), inspect and migrate them before starting an agent:

```sh
~/.guardfil-local/bin/guardfil-broker migrate-ledger --provider all --dry-run
~/.guardfil-local/bin/guardfil-broker migrate-ledger --provider all
```

  Brokers fail closed if an unmigrated legacy ledger is present so existing spend
  accounting and halt states are never bypassed by opening a fresh `$2.00`
  ledger.

## New since alpha.3

- **Prompt broker shutdown on `SIGTERM`.** `MessagesBrokerServer.RequestStop`
  and `NeutralBrokerServer.RequestStop` now track and close the Unix socket
  listener under a dedicated `stopMu` (separate from the in-flight request
  lock), waking `Accept` immediately instead of timing out teardown waits.
- **OpenAI `responses` SSE error diagnostics.** `ParseAndValidateSSEDetailed`
  extracts response identifiers (`response_id`, `model`, `service_tier`),
  fixed parse-failure reason categories, and finite allowlisted upstream error
  metadata (`upstream_error_type`, `upstream_error_code`, mapping unrecognized
  tokens to `other` and never reading raw error `message` text or prompts),
  scrubbing any broker credential or key-shaped token across outputs. Fail-closed
  `INVALID_RECEIPT_EVIDENCE` retention and ledger halts remain unchanged while
  recording `response_id`, `model`, `service_tier`, `parse_error`,
  `upstream_error_type`, and `upstream_error_code` into broker evidence JSONL;
  `parse_error`, `upstream_error_type`, `upstream_error_code`, and `response_id`
  to stderr; and `error`, `detail`, plus optional `upstream_error_type` /
  `upstream_error_code` in the HTTP 502 JSON reply.
- **Provider ledger naming & schema-v2 migration.** Provider ledgers now use
  provider-named directories (`~/.local/state/guardfil/{openai,anthropic,gemini}/`)
  and identifiers (`guardfil-{openai,anthropic,gemini}-v1`), backed by schema v2
  (`MIGRATED` journal record, `legacy_experiment_id`, preserved historical
  witness/replay checks, incremented inspection generation floor, `RENAME_NOREPLACE`
  publishing, target-to-backup provenance verification, read-only `--dry-run`
  inspection, and a `migrated_to.json` + retired `ledger/` scaffold keeping both
  migrated and fresh v2 installations non-reinitializable by older binaries). Adds
  `guardfil-broker migrate-ledger` (`--provider`, `--dry-run`, `--state-root`)
  and updates broker open behavior, `--experiment-root` provider-root guards,
  demo, and red-team ledger paths.
- **Local startup `--no-build` & bridge-DNS docs.** `guardfil-local.sh up [--no-build]`
  lets users start a pre-built `guardfil-local:dev` image cleanly without
  rebuilding; the updated [troubleshooting](../guide/troubleshooting.md) guide
  documents `--network=host` pre-building and legacy ledger migration resolution.

Everything in [alpha.3](v0.1.0-alpha.3.md) is still included.

## Known limits

- **Local, single-user deployment.** The quickstart UI uses loopback HTTP.
  Remote hosting and SSO are outside this alpha's scope.
- **Host setup & OS coverage.** `user_allow_other` is a host-wide FUSE option
  that needs an administrator. Only Linux (Ubuntu 24.04) has been exercised;
  other Linux distributions remain untested.
- **Commands.** An allowed program can still run its own code. Command rules
  match what GuardFil can resolve from the command line.
- **Model provider.** Data the agent may read can be sent to the model
  provider unless its path is local-only. Local-only access stops cloud turns;
  it does not switch to a local model or recall data already sent. Directory
  listings and lookups count as access.
- **Filesystem and raw mounts.** Escaping links, cycle-bearing directory
  symlinks, relative link targets with `..` after a normal component, device
  nodes, kernel API mounts, other FUSE sources, extended attributes and shared
  mmap are refused or unsupported. Alias expansion and raw-mount hard-link
  inspection are bounded at 1,024 entries; shared storage not visible in
  `/proc/self/mountinfo` (such as an overlay lower directory or the same
  network export mounted twice) is not detected. Mount topology must stay
  stable during a run, and large-workspace performance has not been
  characterized. See
  [filesystem alias limits](../guide/workspace-and-commands.md#filesystem-alias-limits).
- **Host-run rules and policy migration.** The starter policy's host-run blocks
  do not cover build files you run yourself (`Makefile`, `package.json`
  scripts, `.npmrc`), arbitrary `.code-workspace` filenames or every
  application-specific config name. Existing installations must merge new
  starter rules explicitly.
- **Result filtering.** Native shell and file-tool results cannot be filtered.
  Response-content rules on those calls fail with `TRANSFORM_UNAVAILABLE`;
  scope them to MCP, the gateway or the Python `guard` client.
- **Website scope.** Rules cover supported HTTPS URLs at the gateway and the
  initial managed WebFetch URL. Redirects, URL-shaped MCP arguments and
  allowed shell commands are not covered.
- **Accounting.** Ambiguous billing or malformed upstream SSE streams retain the
  reservation and halt the ledger fail-closed. Deterministic Go-ledger write,
  sync, close, rename, and migration crash-recovery tests pass, but real
  power-loss and storage-hardware durability are untested.
- **Audit coverage.** Subsequent bounded AI reviews covered the executor,
  host-file policy, mediated filesystem, runtime mounts, broker shutdown,
  SSE error diagnostics, and ledger migration, with their reported findings
  resolved before release. A follow-up independent filesystem re-review was not
  completed across the final diff, and no comprehensive or third-party security
  audit has been performed. Use disposable, non-sensitive workspaces for
  evaluation. Claude Code refused the model-driven adversarial prompt; its
  adversarial coverage is scripted.

Report vulnerabilities privately; see [SECURITY.md](../../SECURITY.md).
