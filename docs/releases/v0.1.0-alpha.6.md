# GuardFil v0.1.0-alpha.6

GuardFil runs on Linux with Docker and FUSE for single-user evaluation. This release fixes an intermittent startup error when two agents first open the same provider ledger. It includes the migration, broker and Go 1.27.4 updates prepared for alpha.5.

## Install or upgrade

Follow the [tagged quickstart](https://github.com/reviaro/GuardFil/blob/v0.1.0-alpha.6/README.md#quickstart). Existing installations should rebuild the image and extract the new host helpers by running `deployments/local/guardfil-local.sh up` from the new checkout.

If you have provider ledgers from alpha.3 or earlier, stop active agents and inspect the planned migration before applying it.

```sh
"${GF_HOME:-$HOME/.guardfil-local}/bin/guardfil-broker" migrate-ledger --provider all --dry-run
"${GF_HOME:-$HOME/.guardfil-local}/bin/guardfil-broker" migrate-ledger --provider all
```

Existing schema-v2 ledgers keep their balances, reservation counts, and halt status. An interrupted alpha.4 installation that lacks matching recovery records still requires a known matching backup.

## Changes

- Concurrent first opens now share one ledger. A read-only migration inspection during startup can report the provider as new or validate the initialized ledger. An existing target with a missing retirement record continues to fail closed.

- Healthy legacy ledgers must have settlement records that match their journal before migration. The dry run performs the same settlement checks.
- Interrupted first-time initialization and migration of an empty or evidence-only legacy directory can resume without giving an existing ledger a second spending allowance.
- The Claude Messages broker streams signed thinking blocks in the order the client needs for follow-up tool turns.
- One-shot Codex runs exit with an error when the native agent reports a failed or interrupted turn.
- The source build, hosted CI, and default executor use the digest-pinned Go 1.27.4 image.

## Verification

The ledger regression starts eight initializers together with a read-only migration inspection, records one settlement, then reopens the ledger to verify the charge and reservation count. Other tests cover interrupted publication, repeated recovery, mismatched settlement evidence and missing target directories. The public workflow also exercises the executor and the README quickstart.
