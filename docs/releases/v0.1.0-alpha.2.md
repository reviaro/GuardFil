# GuardFil v0.1.0-alpha.2

Second alpha release · 2026-11-11 · GNU AGPL v3

GuardFil runs supported AI coding agents in a constrained executor and applies
owner policy to their shell, file and tool requests. This release puts the
agent's workspace behind a policy-controlled filesystem, so file rules now
apply to everything the agent runs, not only to its file tools. It is for a
single user on a Linux machine with Docker. It is a source release: the
quickstart builds the local container image; no prebuilt binaries or registry
images are attached.

## Install

You need Linux (kernel 5.6+) with FUSE 3, Docker with Compose, Python 3.11+,
and the native agent you want to run installed on the host. CI tested Codex
0.166.0 and Claude Code 2.1.318. Other versions are not covered by this
release's native-agent evidence.

New in this release: an administrator must enable FUSE's `user_allow_other`
option once, so Docker can mount the workspace view.

```sh
echo user_allow_other | sudo tee -a /etc/fuse.conf
git clone --branch v0.1.0-alpha.2 --single-branch https://github.com/reviaro/GuardFil.git
cd GuardFil
deployments/local/guardfil-local.sh check
deployments/local/guardfil-local.sh init --ui active
```

Continue with the [README quickstart](https://github.com/reviaro/GuardFil/blob/v0.1.0-alpha.2/README.md#quickstart)
to add a host-only provider key, start GuardFil and run an agent. Provider
requests cost money and are subject to the spending ledger; each provider
starts with its own $2.00 ceiling.

## Upgrading from alpha.1

- Run `guardfil-local.sh up` to rebuild and extract the new
  `guardfil-workspace` helper.
- Existing policies need an explicit `filesystem.read` grant for
  `/workspace/**`; allowing a read tool no longer grants file access by
  itself. New installations get it from the starter policy. See
  [host setup and existing policies](https://github.com/reviaro/GuardFil/blob/v0.1.0-alpha.2/docs/guide/workspace-and-commands.md#host-setup-and-existing-policies).

## New since alpha.1

- **Mediated workspace.** Reads and writes go through a FUSE filesystem that
  asks policy, including IO from shell commands and from Python code that
  skips the client. File rules apply to resolved objects: hard links and
  links inside the workspace are checked, links leaving it are refused. If the
  view cannot be mounted the agent does not start.
- **Command rules.** Shell rules can allow, block or ask for exact commands
  and prefixes, edited in the web UI. Shell syntax GuardFil cannot resolve is
  blocked when command rules apply.
- **Allow for session.** File approval prompts can grant one exact path and
  operation for the rest of the session. Grants never override a block, are
  listed and revocable in the UI, and end with the session or a rule change.
- **Local-only files.** Paths marked local-only may be used by the agent, but
  after it touches one, that session's cloud model requests, external tool
  calls and gateway calls stop, and what it writes must stay in local-only
  paths.
- **Linux compatibility.** Concurrent sessions on the same or overlapping
  workspaces, ordinary nested storage mounts and bind aliases, files that stay
  open after deletion, and FIFOs and Unix sockets isolated to one view.
- **Setup check.** `guardfil-local.sh check` verifies the host's FUSE setup;
  `init` and `up` warn early instead of failing at the first agent run.

Everything in [alpha.1](v0.1.0-alpha.1.md#included) is still included.

## Verification

The application code is development commit `b088e2e`, which passed all three
hosted CI jobs. Development history from before the public repository is not
published. The public repository starts from a snapshot of this release with
internal development records removed and the developer and operator guides
rewritten; a new installation also starts with no prior provider spend.
On top of that code this release adds the setup check (launcher script and
one Python helper, with a unit test), documentation and a security policy.
The tagged commit's own CI run is on the repository's Actions page.

- 155 browser and headless-restart checks; 32 headless service, CLI,
  Python-client and gateway checks.
- 23 filesystem tests on real FUSE mounts, plus nested tmpfs and bind mounts
  on the CI runner.
- 27 executor escape cases held; the Python runtime passed 11 checks in the
  real executor, including raw IO and shell aliases; the scripted Codex and
  Claude Code red-team suites and command-rule fixtures held.
- Full Go tests, race tests and vet; 111 Python unit tests; clean-runner
  quickstart and reproducibility checks.

These checks use scripted provider stand-ins or mocks. They are bounded
evidence, not a new live-model run or a complete security audit; the last
live-model runs predate the alpha releases. The full Docker workspace flow has run on
CI runners (Ubuntu 24.04) and, after the release was tagged, on one
development host with the same OS and newer agents (Claude Code 2.1.322,
Codex 0.167.0); other distributions are untested. No paid
provider calls were needed.

## Known limits

- **Local, single-user deployment.** The quickstart UI uses loopback HTTP.
  Remote hosting and SSO are outside this alpha's scope.
- **Host setup.** `user_allow_other` is a host-wide FUSE option that needs an
  administrator. Only Linux is supported.
- **Commands.** An allowed program can still run its own code. Command rules
  match what GuardFil can resolve from the command line.
- **Model provider.** Data the agent may read can be sent to the model
  provider unless its path is local-only. Local-only access stops cloud turns;
  it does not switch to a local model or recall data already sent. Directory
  listings and lookups count as access.
- **Filesystem.** Links leaving the workspace, device nodes, kernel API
  mounts, other FUSE sources, extended attributes and shared mmap are not
  supported. Mount topology must stay stable during a run. Alias scans and
  large directory moves can be slow; no performance claim is made.
- **Result filtering.** Native shell and file-tool results cannot be filtered.
  Response-content rules on those calls fail with `TRANSFORM_UNAVAILABLE`;
  scope them to MCP, the gateway or the Python `guard` client.
- **Website scope.** Rules cover supported HTTPS URLs at the gateway and the
  initial managed WebFetch URL. Redirects, URL-shaped MCP arguments and
  allowed shell commands are not covered.
- **Accounting.** Ambiguous billing retains the reservation and halts spend.
  Go-ledger write/fsync failure cases have not yet been tested.
- **Audit coverage.** Confirmed findings are fixed, but two executor/host-file
  audit units remain unreviewed, and the new filesystem code has not had an
  independent audit. Claude Code refused the model-driven adversarial prompt;
  its adversarial coverage is scripted.
