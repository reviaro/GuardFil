# GuardFil v0.1.0-alpha.1

First alpha release · 2026-11-10 · GNU AGPL v3

> This release predates the public repository, and its tag is not published
> here. These notes are kept for history; install
> [v0.1.0-alpha.2](v0.1.0-alpha.2.md) instead.

GuardFil runs supported AI coding agents in a constrained executor and applies
owner policy to shell, file-write and tool requests. This alpha is for a single
user on a Linux machine with Docker. It is a source release: the quickstart
builds the local container image; no prebuilt binaries or registry images are
attached.

## Install

You need Linux, Docker with Compose, Python 3.11+, and the native agent you want
to run installed on the host. CI tested Codex 0.166.0 and Claude Code 2.1.318;
Claude Code 2.1.319 also passed local native checks. Other versions are not
covered by this release's native-agent evidence.

```sh
git clone --branch v0.1.0-alpha.1 --single-branch https://github.com/reviaro/GuardFil.git
cd GuardFil
deployments/local/guardfil-local.sh init --ui active
```

Continue with the [README quickstart](../../README.md#quickstart)
to add a host-only provider key, start GuardFil and run an agent. Use
`--ui none` to initialize without the UI. Provider requests cost money and are
subject to the configured spending ledger; each provider starts with its own
$2.00 ceiling.

## Included

- Native Codex, Claude Code and a Python-agent runtime in the constrained
  executor, with no direct network or provider API keys inside it.
- Per-agent allow, deny, monitor, filtering and owner-approval controls.
  The web UI edits policy and content rules, shows decisions and handles held
  requests. Headless clients and configuration files use the same service.
- Direct admission of actual MCP calls through `guardfil-mcp-proxy`, including
  calls native agents treat as read-only. Denied calls are stopped before the
  tool server runs them, and supported results pass through content filtering.
- An HTTP gateway that applies policy before dispatch, injects app credentials
  and filters replies. Website rules check its actual HTTPS destination and
  the initial URL in Claude Code's managed `WebFetch` hook.
- Host-side OpenAI, Anthropic and Gemini brokers, per-provider spending ledgers,
  model-price checks and conservative accounting when billing is ambiguous.
- A polished web UI with responsive layouts, keyboard navigation, visible
  errors and busy states, and session protection against cross-port cookie
  replay. Policy or content changes invalidate pending approvals.

## Known limits

- **Local, single-user deployment.** The quickstart UI uses loopback HTTP.
  Remote hosting and SSO are outside this alpha's scope.
- **Shell and filesystem scope.** Shell rules allow or block a shell tool,
  rather than individual commands within it. An allowed shell can access the
  workspace. File rules compare names, not resolved objects: symlinks and
  `/proc` aliases are outside their protection. Workspace files can be read
  and sent to the model provider. Review agent changes before running them on
  the host.
- **Result filtering.** Native shell and file-tool results cannot be filtered.
  Response-content rules on those calls fail with `TRANSFORM_UNAVAILABLE`;
  scope them to MCP, the gateway or the Python `guard` client.
- **Website scope.** Rules cover supported HTTPS URLs at the gateway and the
  initial managed WebFetch URL. The gateway does not follow redirects;
  WebFetch redirects, arbitrary URL-shaped MCP arguments and allowed shell
  commands are not covered by these URL checks. See
  [Website enforcement](../guide/policy.md#website-enforcement).
- **Accounting.** Ambiguous billing retains the reservation and halts spend.
  Go-ledger write/fsync failure cases have not yet been tested.
- **Audit coverage.** Confirmed findings are fixed, but two executor/host-file
  audit units remain unreviewed. Claude Code refused the model-driven
  adversarial prompt; its adversarial coverage is scripted.

GuardFil is feasible for this scoped local alpha. Production hardening and
broader filesystem isolation remain future work.
